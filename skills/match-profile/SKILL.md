# match-profile

## When to use
- "Скор слишком завышен/занижен"
- "Хочу изменить порог с 55 до 65"
- "Обнови моё резюме / навыки / предпочтения"
- "Claude неправильно оценивает вакансии по [критерию]"
- "Добавь в матчинг учёт [параметр]"

## Instructions

### Изменить порог совпадения

В `config/settings.yaml`:
```yaml
matching:
  threshold: 55   # ← изменить здесь (55 с 15.08.2026, подобран замером)
```

### Улучшить prompt матчинга

Файл: `src/matcher/cerebras_matcher.py` → константа `_SYSTEM_INSTRUCTION`

Структура системного промта:
1. Контекст кандидата (профиль, проекты)
2. Четыре равноприоритетных направления и выборочные AML/поддержка/QA;
   приоритеты сверять с PROFILE.md. Семь технических ролей предфильтра — отдельная классификация.
3. Шкала оценок (0-100) — **изменяй здесь если скор некалиброван**
4. Штрафы/обнуление score (английский, лидерские роли, чисто-дев роли и т.д.)
5. Формат JSON-ответа

Пример добавления критерия — дописать строку в блок "Score down for: ...".

### Обновить профиль

Начинать с PROFILE.md (мастер). Числа — только из раздела 1a с датой сверки;
фиксированные числа из старых skills и исторических планов не переносить.
Перед правкой личных файлов вне git сохранять локальную резервную копию.

- `config/profile/resume.md` — резюме (используется в каждом запросе через `_build_profile_text()`)
- `config/profile/skills.json` — навыки и уровни
- `config/profile/preferences.json` — зарплата, роли, стек, формат работы

После изменения файлов профиля нужен перезапуск процесса: `_build_profile_text()`
и `_scoring_version()` кэшируются в памяти (`@lru_cache`). Bind-mount доставляет
файлы без пересборки образа, но не обновляет кэш работающего процесса.
Перезапуск и доставку на VPS выполнять только в рамках отдельно разрешённого развёртывания.

### Тест матчинга

```bash
python -m src.matcher.cerebras_matcher --test
```

Перед запуском проверить текущую точку входа и побочные эффекты. Проверки с
вызовами AI API не считать офлайн-тестами; при запрете запуска бота и внешних
действий использовать изолированные проверки с подменой API.

### Оптимизация расхода контекста

Текущая стратегия (менять осторожно):
- Батч: 5 вакансий за запрос (`_BATCH_SIZE = 5` в `cerebras_matcher.py`,
  совпадает с `matching.batch_size` в `config/settings.yaml`)
- Профиль кэшируется в памяти процесса через `@lru_cache(maxsize=1)` на
  `_build_profile_text()` — не путать с серверным prompt caching API
- Pre-filter отсекает нерелевантные до AI (`src/matcher/pre_filter.py`)
- Города стран релокации: локальный проверенный справочник
  `config/hh_relocation_areas.json`; сеть в рантайме не используется. Его содержимое
  входит в версию предфильтра. При обновлении справочника учитывать кэш процесса.
- Результаты кэшируются в SQLite (`storage.get_cached_match`/`save_match`) —
  повторная оценка зависит от версии скоринга: отпечаток промпта, профиля и
  criteria.yaml инвалидирует старые оценки при изменении
- Чекпоинт после каждого батча в `data/matches.jsonl` — безопасный рестарт без
  повторной обработки

Провайдеры заданы в реестре `cerebras_matcher.py`; порядок по умолчанию —
OpenRouter, затем Cerebras, с переопределением через окружение. По PROFILE.md
основной провайдер на 29.10.2026 — OpenRouter. Фактическую конфигурацию VPS
нельзя выводить из имени модуля или примеров; секреты не печатать.
SQLite-кэш уменьшает повторные расходы с учётом версии скоринга.
